Automatic swimming - ACNH 3.0.3 - development test

Setting auto_swim=true defaults on; the regular file and custom overlay use
strict boolean parsing, duplicate rollback, and atomic invalid-file rejection.

Verified local main-relative bindings:
  02367E3C: surface stroke A-press branch (W9 bit 0), in 02367C08.
  0236D558: underwater stroke A-press branch (W8 bit 0), in dive wait update.
  0241E98C: player parameter accessor (argument 1).

Surface wait 0236B77C calls 02364B10 for analog movement, then 02368110 for
water exits and 02367C08 for stroke/dive requests. Surface stride update
0236BEA0 also calls 02367C08. The stroke request selects action F7; the later
Y branch selects F9. Dive wait also calls 02364B10 and selects action FB for
a stroke. Both stroke gates sit after their native input lock at player+17AC;
underwater also retains its resident restriction. The hook changes only a
register at the A branch, leaving all input masks, Y and request construction
untouched. Native scheduling determines when another stroke can start.

The movement routines use player+12F8 to enable player+EEC's float stick pair,
and player parameter +120 for the analog deadzone. Parameter objects provide
the value through virtual slot F0. Native update mode 1 skips local updates;
the hooks also reject it. NaN, infinity and invalid deadzones fail closed.
Exact gate/helper instruction fingerprints are checked before either hook is
installed, so a conflict disables only automatic swimming.

Validation: compiled hooks and native conditional branches at two ASLR bases;
surface/underwater cardinal and diagonal intent, native deadzone, neutral stick,
release/repeat, physical A preservation, disabled input, remote update mode,
invalid analog values, independent config/overlay and compatibility conflicts.
Core integration and other Controls regressions run against the same ELF.
Loaded parameter resources are modeled. Continuous stroke cadence, swimming
animations, diving/catching/surfacing, shore exits and multiplayer require live
Eden testing; no live result is claimed.

Prototype 2: surface only

Live feedback reported a pause between automatic underwater strokes and a need
to turn in place while chasing creatures. Remove the underwater hook and its
compatibility dependency entirely. auto_swim remains true by default and only
extends the surface stroke gate. Underwater A/Y input, timing and turning now
use the original game code. Returning to the surface resumes auto-swimming.
Tests retain native underwater branch/request construction with physical A,
verify tilted sticks cannot synthesize underwater strokes, and confirm that
an underwater gate conflict does not disable the independent surface hook.
The preceding underwater hook details document prototype 1 only.

Prototype 3: strong stick, held A and smooth diving

Live feedback requested automatic underwater swimming again, with strong stick
intent and fewer audible arm strokes. The previous press-gate hooks are replaced
by scoped C++ trampolines on surface wait/stride updates (0236B77C/0236BEA0),
underwater wait/stride updates (0236CF20/0236DB00) and their stride entries
(0236BBB8/0236D6A0). The input-enable, local update mode, input-lock and eight
resident bounds checks are retained. Physical A bypasses automatic policy.

At >=.85 stick magnitude, borrow logical held A bit 0 within the synchronous
swimming update/entry, and press A once every 38,400,000 Horizon system ticks
(two seconds). Restore the borrowed input bits and held-frame count afterwards,
without overwriting other native input writes. Identity is tied to player
pointer, generation handle and surface/underwater mode. Light tilt clears the
automatic run so the next strong push starts with an arm stroke.

Native stride entry selects PlayerSwimStride_FlapFoot/PlayerDiveStride_FlapFoot
when action-0's held counter at player+13D8 exceeds 30. Scoped counter 31 enables
that quiet selection, except within 200ms of the periodic pulse (counter 0) so
the next native entry can choose the normal arm stroke. This is animation
selection, not global sound suppression or playback-rate modification.

Movement helpers 02364B10/02365878 are wrapped but changed only inside the
current swim scope. Native direction calculation executes unchanged. For a
light tilt, current speed at 1820 and target speed at 1844 are zeroed so native
slow drift or residual stroke speed does not defeat turning in place. During
automatic diving, StrideMovement's first float gives the native slow cruise
speed, including the FlapFoot scale. Retain this as a minimum for current and
target speed through subsequent wait/stride frames. Preserve faster native
arm acceleration, collisions, reservations and state transitions. This targets
the reported deceleration pause; actual perceived smoothness needs live testing.

Tests run compiled scopes/restoration/movement policy at two ASLR bases with
modeled native updates and speed parameters. The real native held-A branch and
arm-vs-FlapFoot selector fragments execute. Check strong/light cardinal and
diagonal input, invalid analog input, two-second pulses, pending-pulse entry,
cruise across wait frames, release, unchanged manual A, blocked/remote input,
shared movement outside swimming, config and all eight dependency conflicts.
Actual audio, transition cadence, collision response and catching need Eden.


Prototype 4: acknowledge arm strokes at native stride entry

Live feedback confirms improved underwater smoothness but only the initial arm
stroke. Prototype 3 expired the arm selector override after 200ms and emitted
just one fresh A press at each timer deadline. Native surface/dive stride code
only considers another A-driven stride while StrideMovement returns <=1 (see
0236C214 / 0236DEF4). A pulse during the remaining animation can be skipped;
even a later held-A transition would then select FlapFoot after that window.

Latch an arm request, repeat the scoped fresh A bit while it is pending, and
keep counter 0 until SurfaceEntry/DiveEntry actually runs. Consume the request
only after native entry, starting the next two-second interval at that entry.
Ordinary entries between deadlines use counter 31. Light tilt and physical A
cancel pending automatic strokes. Recognize an already active synthetic scope
so a synchronous nested entry does not mistake borrowed A for physical input.
The strong-stick threshold and underwater cruise floor remain unchanged.

Compiled regression exercises three recurring strokes per swim mode at two
ASLR bases, including delays of 500ms before entry (longer than the old window),
quiet intermediate entries, input restoration and continuous underwater cruise.
Native update/animation timing is modeled and the actual animation selectors
execute. Live validation of recurring arm animation and sound remains pending.


Prototype 5: analog swimming with manual stroke boosts

User requests a swimming rework: analog speed like land movement, one opening
stroke on starting to move, then manual A boosts with a ~2s cooldown; holding A
repeats as soon as ready. This supersedes prototype 4's automatic timed strokes
and the physical-A bypass. The setting remains auto_swim=true by default; false
installs none of these hooks and retains all native swimming behavior.

StickThrottle applies a .15 radial dead zone, then linear (magnitude-.15)/.85,
clamped to 1 for diagonal overtravel. This is a playtest tuning choice; steering
still executes the native stick handling. Nonfinite/corrupt inputs yield zero.
The shared movement wrappers replace current/target speed after native steering
with cruise * (throttle + .25 * boostEnvelope). BoostEnvelope decays linearly
from 1 to 0 over 9,600,000 ticks (half a second) following accepted arm entry.
This removes animation-driven deceleration at both surface and depth. A neutral
manual boost uses native facing. Quiet cruise is learned from StrideMovement
slot zero; normal arm entry passes full base speed, whereas FlapFoot callers
scale by .8. Normalize arm parameters by .8, keeping the same cruise regardless
of animation. Native request results, steering and other action updates remain.

A ready physical press/hold latches an arm request until stride entry, even if
a tapped button is subsequently released. Early taps during cooldown are
ignored. Holding A retries when ready; automatic stick-only swimming never
schedules later periodic arm strokes. An opening stroke also consumes the same
cooldown so stop/start cannot spam boosts. Diving/surfacing preserves cooldown
while relearning cruise speed for the new mode. A half-second gap between swim
callbacks resets session movement/pending state without clearing cooldown.
Y press clears queued strokes and suppresses borrowed A that update, allowing
native diving/surfacing/catching priority. All borrowed A bits and frames are
restored after the synchronous native call; guarded/nonlocal input is untouched.

Compiled checks at two ASLR bases cover analog cardinal/diagonal scaling and
invalid input, delayed opening and manual strokes, six seconds with no further
automatic arms, ignored cooldown taps, three held-A boost cycles, impulse decay,
quiet/native arm selectors, wait-frame continuity in both modes, neutral thrust,
stop/start and mode-change cooldown preservation, Y priority, nested entries,
input restoration, guards, config layering and all hook dependency conflicts.
Native world movement/animation timing is modeled. In-game feel, collision and
creature interaction validation remain pending.
